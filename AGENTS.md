# AGENTS.md

Context for AI agents working on this repository.

## Project Overview

Neuromatch Course Guide: the manual and showcase for building a course with MyST (Markedly Structured Text). MyST `.md` files in `guide/` are the single source of truth. Jupyter notebooks (`.ipynb`) are generated artifacts, never authored directly. The rendered book deploys to GitHub Pages via CI.

The tooling (MyST plugin, `nma-kit` CLI, CI workflows) is the published **Neuromatch course kit** ([neuromatch/course-kit](https://github.com/neuromatch/course-kit)): npm `@neuromatch/course-kit` and PyPI `neuromatch-course-kit`. **This repo contains no kit code.** It holds content, configuration and authoring documentation only; fix kit behaviour in the kit repo, not here.

**Courses never fork or copy this repo.** A new course runs `nma-kit init` (kit >= 0.1.9; this book follows 0.4), which writes a minimal starter (`myst.yml`, `.github/workflows/course.yml`, `requirements.txt`, README checklist, one example day, a projects stub) into a fresh repository. Never write "fork this template" in the text; point to `guide/maintainer/create-a-course.md`. Keep this book's `myst.yml` and `course.yml` close to what `init` generates, so it stays a faithful reference (the only deliberate difference is folder names: this book has one content folder, `guide/`, instead of `tutorials/` and `projects/`), and don't hardcode this repo's values (feedback project, GitHub URL) in advice to authors. This file covers authoring conventions; for kit internals read the kit's `AGENTS.md`.

## Architecture

```
myst.yml                    # Single config: extends the kit's nma.yml, metadata, TOC, nma: settings
                            # (nma.content: [guide] = the only folder the kit processes)
guide/                      # Every page of the book (static ones too); organised by audience
  index.md                  # Landing page
  start/                    # What the kit is, which path to follow
  author/                   # Quick start and the how-to pages for people who write content
  maintainer/               # Create a course, CI, previews, instructor site, branding, upgrades
  instructor/               # What instructors get
  reference/                # Directives, frontmatter, nma: settings, CLI, check rules, browser limits
  examples/                 # Showcases and the validated source behind the feature pages
    directives/             # Example pages whose regions the feature pages show (see below)
    lds/, colab/            # A real tutorial as a normal page and as a scrolly page; a Colab page
    projects/               # Project booklet examples
  <section>/images/, data/, slides/   # Figures, small data files ({nma-data}) and slide PDFs ({nma-slides} :path:) beside the pages that use them
_wheels/                     # Pre-built .whl files for Pyodide (CORS-friendly hosting)
_nma/                        # Generated by `nma-kit sync-assets` (kit stylesheet, logos, favicon); self-ignoring, never committed
notebooks/                   # Generated files (gitignored, lives on notebooks-branch):
                             #   guide/<folder>/<page>.ipynb, .../instructor/<page>.ipynb, .../solutions/*
docs/superpowers/            # Design spec, implementation plan, conventions.md, verify.sh (not built, not a content folder)
.github/workflows/
  course.yml                 # Calls the kit's reusable workflows: PR check; on main: notebooks -> notebooks-branch, site -> Pages
  wheels.yml                 # Manual: build Pyodide wheels into _wheels/ (kit workflow)
```

Pages outside a folder listed in `nma.content` are ignored by the kit (no checks, no notebook), so every page lives under `guide/`. `nma.content` is required since kit 0.4.

### Key files

- **`myst.yml`** -- the only config file. Contains project metadata, hand-authored TOC, the kit's config (`extend: https://cdn.jsdelivr.net/npm/@neuromatch/course-kit@0.4/dist/nma.yml`, which adds the plugin and `project.jupyter.lite: true`), site theme, and the top-level `nma:` block (settings read by the course kit, not by MyST, which logs `extra key ignored: nma`). There is no `_toc.yml` or `_config.yml`.
- **`nma-kit`** -- the course kit CLI, run from the repo root: `check` (content rules below), `notebooks` (student/instructor notebooks and solution files, badges from `project.github`), `render-scrolly`, `prepare-site` (CI only: badges + run-all fallback cell in the `.md` pages), `publish-notebooks`, `finalize-site` (CI only: `robots.txt`, no sitemap, `noindex` for the instructor site), `sync-assets`, `init`.
- **`.github/workflows/course.yml`** -- calls the kit's reusable workflows (`@v0.4`), which install the matching `neuromatch-course-kit` and run the `nma-kit` steps (see "Build & CI").
- **`requirements.txt`** -- the packages the pages import (numpy, matplotlib, ...). The tooling (mystmd, pinned by the kit; jupytext; nbclient) comes from the course kit.
- **`.nvmrc`** -- Node.js version (22). MyST requires Node >= 20.

## Key Conventions

### Frontmatter reference

| Key | Values | Read by | Effect |
|---|---|---|---|
| `title` | string | MyST | Page title (always set it). |
| `kernelspec` | `name: python3`, `display_name: Python 3` | MyST, course kit | Makes the page executable: editable cells, generated notebooks, badges. Required if the page has a `{code-cell}`. |
| `runtime` | `browser` (default), `colab` | course kit (cells) | `colab` = read-only code plus a Colab/Kaggle banner, no fallback cell. Not with `layout: scrolly`. |
| `layout` | `scrolly` | course kit (scrolly) | Scrollytelling page. Pair with `site: {hide_outline: true}`. |
| `feedback_prefix` | string | course kit (feedback) | Overrides the prefix of `{nma-feedback}` ids. |

MyST logs `extra key ignored` for `runtime`, `layout` and `feedback_prefix`; that is expected. The user-facing version of this table is `guide/reference/frontmatter.md` (and `guide/reference/directives.md` for directives): keep both in sync when a key is added.

### Executable vs static pages

A page with `kernelspec` in its YAML frontmatter is executable:

```yaml
---
title: "Some Topic"
kernelspec:
  name: python3
  display_name: Python 3
---
```

This means:
- every code cell becomes an editable, runnable panel (see "Editable cells"), unless the page sets `runtime: colab`
- `nma-kit notebooks` generates a `.ipynb` from it
- CI injects Colab/Kaggle badges

A page without `kernelspec` is static (chapter intros, further reading, bonus pages without code).

### Content rules (enforced by CI)

`nma-kit check` validates these rules (so do `nma-kit notebooks` and `prepare-site`, before doing anything) and exits non-zero on any violation:

- **No `.ipynb` in `guide/`.** All content is MyST `.md`. Convert incoming notebooks once (see "Converting .ipynb to MyST .md") and commit only the `.md`.
- **Pages with code need `kernelspec`.** A `.md` file with a top-level `{code-cell}` must declare `kernelspec`. Code-cells shown as examples inside another fenced block don't count.
- **Exercises need solutions.** Every top-level exercise code cell (an uncommented `raise NotImplementedError` line) must be directly followed by an `{nma-solution}`, and every `{nma-solution}` must directly follow an exercise. No `# to_remove` markers may be left in code cells. Solution bodies must be a single ```` ```python ```` fence, explanations can't be empty, and neither directive may be nested or take options.
- **Media directives must be valid.** Every top-level `{nma-video}` needs a title and at least one of `:youtube:`/`:bilibili:`/`:osf:`. Every `{nma-slides}` needs `:osf:` and/or `:path:` (a `.pdf` inside the day folder's `slides/` folder, no absolute path or `..`, and the file must exist); there is no `:title:` option. Unknown options, body text and unclosed blocks are errors, reported with file and line.
- **Feedback uses the directive.** `{nma-feedback}` takes a section name (`[A-Za-z0-9_]+`, unique per page), at the top level, with no options or body. No code cell may call `content_review(`, import `vibecheck`, or be an "Import feedback gadget" cell. If any page uses `{nma-feedback}`, `myst.yml` must have `nma.feedback.{url,project,user_key}`, and the `nma:` block must be `section:` mappings of `key: value` with string values (no numbers, lists or deeper nesting).

- **`runtime` must be valid.** Frontmatter `runtime:` is `browser` (default) or `colab`, and `colab` can't be combined with `layout: scrolly`.
- **Scrolly pages must be valid.** `{step}`/`{stage}` only on pages with `layout: scrolly`, at the top level. `{step}` takes no argument or `hero`, only `:section:`/`:kicker:`, and no body. At most one `{stage}` per step (options `:style: list`, `:class:`), none before the first step. A `layout: scrolly` page needs at least one `{step}`. On scrolly pages, every `# @param` line must parse (see "Scrollytelling pages").

There is no Binder, JupyterHub, or remote-kernel support. Code runs in the browser (editable cells on JupyterLite's kernel), and Colab/Kaggle (via the generated notebooks) is the fallback for anything Pyodide can't run.

### Editable cells

Every visible code cell on a **browser page** (has `kernelspec`, not `layout: scrolly`, not `runtime: colab`) is a CodeMirror 6 editor with a **▶ Run** button (Shift-Enter / Ctrl-Enter too). It runs on the JupyterLite kernel that MyST already ships (thebe-lite, Pyodide 0.27), one kernel per page. The JupyterLite power button is hidden by the kit's stylesheet (`_nma/site.css`). Keep `project.jupyter.lite: true`, since MyST only emits the thebe assets with it.

- **Colab pages.** A heavy tutorial adds `runtime: colab` to its frontmatter (MyST warns `extra key ignored: runtime`, expected). It shows read-only code and an "important" admonition, *Do this tutorial in Colab*, that links to Colab and Kaggle. No fallback cell is added. `guide/examples/colab/heavy-compute.md` is an example.
- **How a Run works.** Like a notebook: earlier cells that haven't run go first, then the target. An earlier *unfinished* exercise runs its `{nma-solution}` through the kernel-side fallback cell from `nma-kit prepare-site`. The cell the student explicitly runs gets a trailing `# nma-no-fallback` line, which switches the fallback off for that cell, so a partly edited exercise shows `NotImplementedError` and never the solution. Running stops at the first earlier cell that fails.
- **Modes by tag.** none = editor + output, `hide-input`/`hide-cell` = editor behind "Show code", `remove-input` = output only (Run button), `remove-cell` = no panel, runs as an earlier cell. Exercises get an accent colour and the label "Exercise · fill in, then run".
- **Edits live in memory only**, per page (Reset restores the original). Changing page disposes the kernel and starts a fresh one when you come back. **Restart** starts a new kernel session.
- **Styling.** CSS variables with light and dark defaults (`html.dark`/`html.light`), overridable from your own CSS (`nma.style.extra` in `myst.yml`, e.g. `_static/extra.css`): `--nma-cell-{bg,fg}-{light,dark}`, `--nma-cell-border-{light,dark}`, `--nma-cell-radius`, `--nma-cell-accent-{light,dark}`, `--nma-cell-exercise-accent-{light,dark}`, `--nma-cell-bar-{bg,fg}-{light,dark}`, `--nma-cell-gutter-{bg,fg}-{light,dark}`, `--nma-cell-active-line-{light,dark}`, `--nma-cell-head-{bg,fg}-{light,dark}`, `--nma-cell-bar-bg-{light,dark}`, `--nma-cell-out-bg-{light,dark}`, `--nma-cell-font-family`, `--nma-cell-font-size-value`, `--nma-tok-{keyword,string,number,comment,function,definition}-{light,dark}`. Example: `:root { --nma-cell-accent-light: #2a9d8f; --nma-tok-keyword-light: #b5179e; } html.dark { --nma-tok-keyword-dark: #f72585; }`.
- **Outside services** (students' browsers must reach them): `cdn.jsdelivr.net` (Pyodide 0.27, widget JS), `cdnjs.cloudflare.com` (`require.js`, MathJax, font-awesome), `pypi.org`/`files.pythonhosted.org` (`micropip`). Scrolly pages load their own, newer Pyodide, so package availability can differ.
- **Internals** (bundles, asset URLs, browser smoke test): see the kit's `AGENTS.md`.

### Badges

Never add or commit badge HTML in `.md` files. The `.md` sources on `main` are badge-free. Badges are added at build time in two places:
- **Generated notebooks**: `nma-kit notebooks` inserts a badge cell at position 0 of each `.ipynb`.
- **Rendered site pages**: CI runs `nma-kit prepare-site` right before `myst build`, on its throwaway checkout. The result is never committed.

Every page with `kernelspec` gets badges automatically, so local `myst start` previews show no badges.

### Videos and slides

Never write video or slide players as code cells. Use the directives:

```markdown
:::{nma-video} Video 1: Linear Dynamical Systems
:youtube: 87z6OR7-DBI
:bilibili: BV1up4y1S7wj
:::

:::{nma-slides} Tutorial slides
:osf: snv4m
:path: slides/deck.pdf
:::
```

- On the site, the course kit's plugin (the kit's `js/src/media/`) renders them as static iframes (tabs for multiple hosts), so they show without starting JupyterLite.
- In generated notebooks, `nma-kit notebooks` (`nma_kit.media`) replaces them with the standard hidden NMA code cells (ipywidgets Tab / OSF IFrame).
- Options: `nma-video` takes `:youtube:`, `:bilibili:`, `:osf:` (at least one). `nma-slides` takes `:osf:` (an OSF file id) and/or `:path:` (a PDF in the day's `slides/` folder, relative to the day folder), and its argument is the title (default "Tutorial slides"). With both options the site shows one tab per backend.
- `:path:` PDFs are published like `{nma-data}` files, so only pages with a `kernelspec` can use `:path:` (the file is copied when that page's notebook is generated; a static page's PDF never reaches the notebooks branch, and the site then shows "Couldn't find the requested file"): `nma-kit notebooks` copies them to `notebooks/<root>/<folder>/slides/`, and the site and notebooks iframe them from the jsDelivr GitHub mirror (public repos only, branch URLs cached ~12 h). A download link is always shown.
- Put them at the top level of the page (not nested in other directives), with options only and no body.
- Adding a host is a course kit change: `VIDEO_SOURCES` in both `js/src/media/plugin.mjs` and `nma_kit/media.py`.

### Feedback

Never write feedback cells (`content_review(...)`, the vibecheck "Import feedback gadget" cell) by hand. Use the directive:

```markdown
:::{nma-feedback} Linear_Dynamical_Systems_Video
:::
```

- The section id sent is `<prefix>_<name>`. The prefix is the frontmatter `feedback_prefix:` if set (MyST warns `extra key ignored`, which is expected), otherwise derived from the filename: `W<week>D<day>_Tutorial1` -> `W<week>D<day>_T1`, any other stem is used as is. Set `feedback_prefix` when converting an NMA notebook so its ids stay the same.
- Where responses go is set once in `myst.yml`:

  ```yaml
  nma:
    feedback:
      url: https://pmyvdlilci.execute-api.us-east-1.amazonaws.com/klab
      project: neuromatch_cn
      user_key: y1x3mpx5   # write-only, published in every notebook; not a secret
  ```

- **Site:** the course kit's plugin (the kit's `js/src/feedback/`) turns each directive into MyST's `anywidget` node backed by its browser widget. It renders 🙂/😐/🙁 with no kernel and POSTs `{button_name, feedback, section_id, timestamp_utc}` to `<url>/api/v1/projects/<project>` with header `X-User-Key`, the same request vibecheck makes.
- **Notebooks:** each directive becomes a hidden `# @title Submit your feedback` / `content_review(f"{feedback_prefix}_<name>")` cell, and one hidden "Import feedback gadget" cell (`%pip install vibecheck datatops`, `content_review`, `feedback_prefix`) is added at the top. Notebooks only run on Colab/Kaggle/local Jupyter, so it has no Pyodide branch.

### Instructor notes and the instructor site

```markdown
:::{nma-instructor}
Allow 10 minutes. Students often forget the sign.
:::
```

- `{nma-instructor}` takes Markdown, goes at the top level, with no argument or options. It is removed from the student site and from **every** generated notebook, and shows as an "Instructor notes" box on the instructor site.
- The instructor site is a second build of the same course with `NMA_AUDIENCE=instructor` (env only, no `myst.yml` key): `{nma-solution}`/`{nma-explanation}` inline in collapsed boxes, Colab/Kaggle buttons open the instructor notebooks, `robots.txt` disallows everything, `noindex` header, no sitemap. It is **not access controlled**.
- CI deploys it to Cloudflare Pages when the variable `CLOUDFLARE_INSTRUCTOR_PROJECT` and the secrets `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` are set, through the `instructor-cloudflare-project` input of the `publish` and `preview` jobs in `course.yml`. Pull requests then get a second preview (`https://pr-<n>.<instructor project>.pages.dev`). The user-facing pages are `guide/maintainer/instructor-site.md` and `guide/instructor/what-you-get.md`.

### Exercises, solutions and explanations

Never write solutions or explanations as code cells (the old `# to_remove solution` / `# to_remove explanation` convention, which CI now rejects). Use the directives:

`````markdown
```{code-cell} python
def f(x):
  raise NotImplementedError("Student exercise: implement f")
```

::::{nma-solution}
```python
def f(x):
  return 2 * x
```
::::

:::{nma-explanation}
Markdown answer to a discussion question, math allowed: $a < 0$.
:::
`````

- The exercise is a normal untagged `{code-cell}`. The `{nma-solution}` goes directly after it, with only blank lines in between. Its outer fence needs more colons than the inner ```` ```python ```` fence.
- `{nma-explanation}` stands alone, usually after an interactive demo or a "Think!" question.
- Both go at the top level of the page, with no argument and no options.
- **Site:** a *Click for solution/explanation* link to `notebooks/<root>/<folder>/solutions/<page>_Solution_<n>.py` / `<page>_Explanation_<n>.md` on `notebooks-branch`, where `n` counts each directive type from the top of the page. The answer isn't shown on the page.
- **Student notebook:** the same link as a markdown cell. **Instructor notebook** (`notebooks/<root>/<folder>/instructor/`): the solution as a code cell starting with `# Solution`, and the explanation as markdown under **Explanation**.
- **Run-all fallback (site only):** `nma-kit prepare-site` adds a hidden `remove-cell` setup cell to pages with exercises. It registers an IPython input transformer: while a cell still has an uncommented `raise NotImplementedError` line, the matching reference solution runs instead (exact match, else the closest by `difflib` ≥ 0.6), so "Run all" in JupyterLite doesn't stop. The solutions are hidden, not secret.

### Scrollytelling pages

Opt in with `layout: scrolly` in the frontmatter, plus `site: {hide_outline: true}` (MyST warns `extra key ignored: layout`, which is expected). The page stays a flat tutorial. `{step}` markers split it into steps, and each step is a **card** (prose) plus a pinned **stage**. The how-to page is `guide/author/scrolly.md` (itself a scrolly page), and `guide/examples/lds/scrolly-page.md` is a full example.

```markdown
:::{step} hero
:kicker: neuromatch academy
:::
# Title

:::{step}
:section: One dimension
:kicker: Coding Exercise 1
:::
Card text. Code cells, images, figures, {nma-video}/{nma-slides} after the
marker go on the stage; prose, math, solution links and {nma-feedback} on the card.

:::{stage}
:style: list
1. Stage-only markdown
:::
```

- The section is placed between the book theme's TOC sidebar and "On this page" outline (`.scrolly-col` in `scrolly.css`), and its layout uses container queries on its own width: stage beside the cards from 760px (`WIDE` in `engine.mjs`), stacked below that. Scrolly pages should set frontmatter `site: hide_outline: true` to give the section the outline's space, but not `hide_toc`: with it the theme leaves the TOC out of the page entirely (no sidebar, and the small-screen menu opens empty), so readers can't move to another page mid-story.
- Engine (HUD), stage and steps share one grid cell (`grid-area: 1 / 1`), not negative margins. A sticky element with `margin-bottom: -height` keeps sticking a screen past its parent and covered the footer prev/next links (regression test in the kit).
- A step with nothing for the stage keeps the previous stage. A `hero` step has no card. Content before the first `{step}` is a normal page header.
- Code cells on the stage: untagged = editable panel, `hide-input` = code collapsed, `remove-input` = output only, `remove-cell` = invisible (runs before the first visible cell).
- Panels share one Pyodide runtime (`nma.scrolly.pyodide_url` in `myst.yml`). Running a cell first runs earlier unrun cells. An earlier unfinished exercise runs its `{nma-solution}` instead. JupyterLite's power button is hidden on these pages.
- Interactive demos use Colab form syntax, one top-level assignment per line: `a = -0.5  # @param {type:"slider", min:-2.5, max:1.5, step:0.25}` (`step` defaults to 1) or `option = 1  # @param [1, 2, 3, 4]` (the default must be in the list). Never use `@widgets.interact` on scrolly pages. Notebooks get `widgets.interact` automatically.
- **Never hand-write outputs.** `nma-kit render-scrolly` runs each scrolly page's instructor notebook (exercise cells removed, `# @param` at defaults, cwd = page dir) and writes `_build/scrolly/<relDir>/<stem>.json` = `{cell_key: {stdout, images, error}}`. A raising cell fails CI with `file:line`. Exercise cells get no starting output.
- The `cell_key`, `# @param` grammar and render-path rules shared by the kit's Python and JS sides are in the kit's `AGENTS.md`.
- Notebooks: markers are removed (a `:kicker:` becomes an italic line), `{stage}` blocks are unwrapped, and `# @param` cells become `widgets.interact`. Avoid "on the right"/"on the stage" in card text, since the notebook shows it too.

### Images and data files

Keep a day's images, data and slide PDFs in that day's folder, in `images/`, `data/` and `slides/` (names set by `nma.assets.image|data|slides`; or directly beside the page for one or two files), referenced by paths relative to the page. Relative paths work on the site and are the working directory for executed code. Only truly site-wide files (custom logo, `nma.style.extra` CSS) go in a root `_static/`, created when needed.

- **Declare the files a page's code reads** with `{nma-data}` (one path per line, in `data/` or `images/`). On the site, files up to 2 MB are embedded for the page's editable cells, so `np.load('data/x.npz')` just works. In notebooks, `nma-kit notebooks` copies the files to `notebooks/<root>/<folder>/` on the notebooks branch and adds a hidden download cell. Images a page only **displays** (Markdown, `<img>`, `{figure}`/`{image}`) need no declaration: every referenced image is published automatically and Markdown images are rewritten to absolute URLs. `nma-kit check` still rejects references to missing images, undeclared files that code reads, and dynamic paths. See `guide/author/images-and-data.md`.
- Files that are not declared are not in notebooks. Anything else a notebook needs must be an absolute `raw.githubusercontent.com` URL; in the browser fetch data with `pyodide.http.open_url`. See `guide/author/images-and-data.md` and `guide/reference/browser-limits.md`.

### Code cell tags

```markdown
```{code-cell} python
# Regular cell -- fully visible, editable and runnable on the page
```

```{code-cell} python
:tags: [hide-input]
# Code hidden behind toggle, output visible. Used for:
# - Infrastructure (plotting functions, figure settings)
# - Interactive widgets (@widgets.interact)
```

```{code-cell} python
:tags: [remove-cell]
# Completely hidden. Used for setup code (e.g., micropip installs)
```
```

Exercise cells (containing `raise NotImplementedError`) must have NO tags so students can see and edit them.

### LaTeX

MyST uses KaTeX, not MathJax. Common incompatibilities:

| Does NOT work (LaTeX) | Use instead (KaTeX) |
|---|---|
| `\begin{eqnarray}` | `\begin{aligned}` wrapped in `$$` |
| `\begin{array} & a & b` | `\begin{bmatrix} a & b` |
| `\\\\` (double backslash) in `eqnarray` | `\\` in `aligned` |

Always test math rendering with `myst build --html`.

## Build & CI

### Local preview

```bash
# Requires Node >= 20 (use nvm if needed)
export NVM_DIR="$HOME/.nvm" && source "$NVM_DIR/nvm.sh" && nvm use 22
uv venv && uv pip install -r requirements.txt neuromatch-course-kit
uv run nma-kit check       # content rules, as in CI
uv run nma-kit sync-assets # branding (_nma/), once and after kit upgrades
uv run myst start          # Dev server at localhost:3000
uv run myst build --html   # Full build to _build/html/
```

For scrolly pages, run `uv run nma-kit render-scrolly` first so the panels show real outputs (otherwise they show "Run to see output").

### Notebook conversion (local, optional)

```bash
uv run nma-kit notebooks             # Convert all
uv run nma-kit notebooks --dry-run   # Preview only
```

This writes only to `notebooks/` (gitignored) and never modifies `.md` files. `nma-kit prepare-site` edits `.md` files in place and is meant for CI only. If you run it locally, revert with `git checkout -- guide/ myst.yml`.

Kit tests run in the kit repo; see its `AGENTS.md`.

### CI

`.github/workflows/course.yml` calls the kit's reusable workflows at `@v0.4` (newest 0.4.x; use an exact tag like `@v0.4.0` to freeze a course). The kit is still in development: when moving to a new minor version, bump the workflow ref, the `extend:` URL and the local package together, then run `nma-kit check`. `prepare-site` pins the `extend:` URL in `myst.yml` to the same exact version on CI, so plugin, assets and CLI come from one release.

- **Pull requests** (`course-check.yml`): `nma-kit check`, `notebooks --dry-run`, `render-scrolly`, `prepare-site`, `myst build --html`. Nothing is published to the live site.
- **Pull request previews** (`course-preview.yml`, the `preview` job in `course.yml`): builds the PR like a publish, pushes its notebooks to `notebooks-pr-<n>` (every badge and link follows that branch), deploys the site to Cloudflare Pages as `https://pr-<n>.<project>.pages.dev` and keeps one comment with the link. Closing the PR deletes the branch and deployments. Same-repository PRs only. Needs secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` and variable `CLOUDFLARE_PROJECT`; without them the deploy is skipped. With `CLOUDFLARE_INSTRUCTOR_PROJECT` set it also deploys an instructor preview (see "Instructor notes and the instructor site").
- **Push to `main`** (`course-publish.yml`): `nma-kit check` -> `nma-kit notebooks` -> `nma-kit publish-notebooks` (to `notebooks-branch`, created if missing) -> `render-scrolly` -> `prepare-site` -> `myst build --html` -> `finalize-site` -> deploy to GitHub Pages. Each step runs only if the previous one passed, and one publish runs at a time.
- GitHub Pages: Settings -> Pages -> Source: GitHub Actions (custom domain set there; no CNAME copy step).
- Pyodide wheels: `.github/workflows/wheels.yml` (manual) calls the kit's `course-wheels.yml` and commits wheels to `_wheels/`.

### Adding a page

1. Pick the section it belongs to (`guide/author/`, `guide/maintainer/`, ...) and create the `.md` file with a plain slug name. The file stem becomes the notebook name, the `<stem>_Solution_<n>.py` file name and the default `{nma-feedback}` id prefix, so set `feedback_prefix` if you rename a page that has feedback widgets.
2. Add a `- file:` entry in `myst.yml` under `project.toc`, as a child of the section's `index.md` (the section's parent entry; don't wrap it in a `title:` group, because that makes the section appear twice in the sidebar).
3. Validate: `docs/superpowers/verify.sh` (check, notebooks, render-scrolly, build, stale-name grep, relative links, region markers), or at least `uv run nma-kit check`.

### Page structure

Guide pages follow the template in `docs/superpowers/specs/2026-11-02-guide-restructure-design.md` (section 5): a `For:` label, a short intro, **You write**, **You get**, **Rules**, **Next**. "You write" shows source from a real example page with a literal `{include}`: see `docs/superpowers/conventions.md` (region markers `% region-start: <name>`, `:lang: text`). Pages that use `{include}` must be static (no `kernelspec`): an executable page's notebook would contain the raw include. Never plain-include `{nma-feedback}`, `{nma-solution}` or `{nma-explanation}`.

## Pyodide / JupyterLite

### Bundled packages

numpy, matplotlib, scipy, pandas, altair -- available in Pyodide out of the box.

### Packages needing micropip

ipywidgets -- install via micropip in a setup cell. (Feedback needs nothing: the site widget is plain JS.)

### Wheel hosting (CORS)

Micropip fetches wheels from URLs in the browser. **GitHub Releases URLs are NOT CORS-friendly** -- they block `Access-Control-Allow-Origin`. Use `raw.githubusercontent.com` instead, which sends proper CORS headers.

Pre-built wheels live in `_wheels/` and are served via:
```
https://raw.githubusercontent.com/neuromatch/course-kit-guide/main/_wheels/<package>.whl
```

This is a temporary workaround. Once upstream maintainers publish wheels to PyPI, remove the URL workaround and install by package name.

### No sockets: downloading files

Pyodide can't open sockets, so `urllib.request` / `http.client` (and anything built on them, such as `plt.style.use(<url>)` or `pd.read_csv(<url>)`) fail in the browser with `OSError: [Errno 23] Host is unreachable`. Under `sys.platform == "emscripten"`, fetch with `pyodide.http.open_url(url)` (synchronous) or `await pyodide.http.pyfetch(url)`, write the result to a local file, and use that path. `requests` works as is because Pyodide patches it. The host must send CORS headers (`raw.githubusercontent.com` does).

### Setup cell pattern

```python
import sys
if sys.platform == "emscripten":
    import micropip
    await micropip.install(["ipywidgets"])
```

For a package served from `_wheels/`, add `f"https://raw.githubusercontent.com/<org>/<repo>/main/_wheels/<file>.whl"` to the list.

## Converting .ipynb to MyST .md

### Cell mapping

| Notebook cell type | MyST equivalent |
|---|---|
| `"cell_type": "markdown"` | Raw markdown content |
| `"cell_type": "code"` | `` ```{code-cell} python `` |
| Badge cell (position 0) | Omit -- CI injects badges |
| `cellView: "form"` / `# @title` | `:tags: [hide-input]` |
| `# to_remove solution` | `{nma-solution}` directly after the exercise cell (drop the marker line) |
| `# to_remove explanation` | `{nma-explanation}` (turn the docstring into Markdown) |
| `raise NotImplementedError` (exercise) | No tags (students must see/edit) |
| `# @markdown` / `@widgets.interact` | `:tags: [hide-input]` |
| `# @title Submit your feedback` (`content_review(f"{feedback_prefix}_X")`) | `{nma-feedback} X` |
| `# @title Import feedback gadget` | Omit -- generated. Copy its `feedback_prefix` into the frontmatter if it differs from the filename default |
| Video cell (`# @title Video …`, `video_ids = [...]`) | `{nma-video}` directive (copy the ids) |
| Slides cell (`# @title Tutorial slides`, `link_id = …`) | `{nma-slides}` directive with `:osf:` set to the `link_id` |

### Frontmatter

Replace all notebook metadata with clean MyST frontmatter:

```yaml
---
title: "Tutorial N: Title Here"
kernelspec:
  name: python3
  display_name: Python 3
---
```

### Checklist for conversion

1. Strip badge cell (position 0)
2. Add clean frontmatter with `kernelspec`
3. Add Pyodide setup cell if needed (micropip installs)
4. Convert all code cells to `{code-cell}` directives with appropriate tags
5. Replace video and slides cells with `{nma-video}`/`{nma-slides}`, and feedback cells with `{nma-feedback}` (drop the gadget cell, set `feedback_prefix` if needed)
6. Replace `# to_remove solution` cells with `{nma-solution}` and `# to_remove explanation` cells with `{nma-explanation}`
7. Normalize LaTeX for KaTeX compatibility
8. Preserve all prose, math, `<details>` blocks, HTML as-is
9. Put the page in the right `guide/` section and add it to the section's `index.md` list
10. Register in `myst.yml` TOC
11. Test: `myst build --html` -- check for `⛔` errors

For a scrollytelling version, follow the "Converting an existing tutorial" checklist in `guide/author/scrolly.md` (merge setup into one `remove-cell`, add `{step}` markers, rewrite demos with `# @param`, run `--render`).
